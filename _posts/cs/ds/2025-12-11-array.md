# 2.1 The Array As An Abstract Data Type
많은 사람들이 array(배열)를 연속적으로 메모리에 저장된 집합으로 해석한다. 하지만 그것은 구현의 의미에 가깝고 정의로 바라보았을 때에는 다음과 같은 특징을 가진다.

## ADT란
Array를 ADT로 나타내면 (index, value)의 set으로 이루어지며 다음과 같은 연산을 사용할 수 있다.
1. create(dimension, value list)
2. retrieve(array, index)
3. store(array, index, value)

위와 같이 특정한 연산을 정의하여 이를 지원할 수 있는 형태이며, 어떤 명시적인 자료구조를 지정하지 않는다(array로 저장할지, 연결 리스트로 저장할지, map으로 저장할지 등)

## 포인터와는 다른 배열

배열과 포인터는 엄연히 다르다. 하지만 함수 인자 등에서 배열은 포인터로 decay되어 동일하게 사용된다. 이는 70년대 초반의 상황에 대해 상상해보면 다음과 같은 이유 때문이다.
- 메모리 매우 비쌈 (KB 수준)
- 성능 최우선
- 하드웨어 수준의 제어를 원함

이런 상황에서 함수 호출 시 배열 전체를 복사하는 것은 굉장한 낭비였다. 따라서 배열의 첫번째 원소의 주소만을 가져감으로써 기능은 유지하되 크기는 개발자들이 알아서 관리하도록 하였다.
따라서 C에서 사용되는 배열은 ADT에서 정의하는 배열과는 다른 불완전한 구현이다.

Modern 언어들은 메모리 문제가 어느정도 해결되었기 때문에 크기 정보를 함께 전달하는 방식으로 이를 해결하였다

# 2.2 Structures and Unions

여러가지 변수를 하나의 단위 내에 묶기 위해 사용되는 구조이다. Typedef를 통해 이후 선언 시 편리하게 사용할 수 있다. Union은 모든 멤버가 같은 메모리를 공유하여 한 순간에는 하나의 멤버만 의미를 갖게 된다.

## Alignment padding

CPU는 특정 주소 정렬에서 가장 빠르게 읽기 때문에 컴파일러는 CPU가 주소를 빠르게 참조하도록 하기 위해 자동적으로 빈 공간(padding)을 넣어 준다.
Padding이 들어가면 다음과 같이 가장 큰 자료형의 배수 형태로 맞춰진다.

그래서 변수의 declaration 순서도 중요하다. 최적화하기 위한 형태는 큰 순서대로 배치하는 것이다.

```c
struct B {
    char c;
    double d;
    int i;
};
// c (1)
// padding 7
// d (8)
// i (4)
// padding 4
// → 총 24

struct B2 {
    double d;
    int i;
    char c;
};
// d (8)
// i (4)
// c (1)
// padding 3
// → 총 16
```

## Tagged union

Union은 메모리를 아낄 수 있다는 점에서 장점을 가지지만 union을 사용할 때는 자료형을 잘 인지하는 것이 중요하다. 가령

```c
union Data {
    int i;
    float f;
    char c;
};

union Data d;
d.i = 10;
// ... many code lines
printf("%f\n", d.f);
```

이렇게 어떤 값이 들어간 지 모르고 다른 자료형을 출력하는 경우 쓰레기 값이 나올 수 있다. 이를 방지하기 위해 enum을 활용할 수 있다. enum은 내부적으로 정수 0, 1, 2 ...로 표현되며 다음과 같이 사용할 수 있다.

```c
struct TaggedData {
    enum { TYPE_INT, TYPE_FLOAT, TYPE_CHAR } type;  // tag
    union {
        int i;
        float f;
        char c;
    } data;
};

// later..
if (td.type == TYPE_INT) {
    printf("%d\n", td.data.i);
}
```
