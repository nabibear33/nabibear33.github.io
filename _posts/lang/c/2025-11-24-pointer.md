많은 코린이들이 좌절하는 포인터 부분에 왔다. 한 번에 이해하는 건 어려우니까 일단 적어보고 나중에 다시 읽으면서 헷갈리는 개념을 추가하도록 하자.

## 왜 이런 개념이 존재하는가?

### call by value
- 인자를 복사하여 지역 변수를 만들고 이를 연산에 사용한다.
- 직관적이긴 하나 기존 데이터를 수정할 수 없고 큰 데이터를 복사하게 되면 cost도 많이 든다.

### call by reference
- 주소를 참조하여 직접 데이터에 접근하여 수정할 수 있다.
- call by value와 비교하여 cost를 아낄 수 있다.

Call by reference가 가지는 이점이 존재한다.

## Pointer와 Array의 차이점은 뭔가
보통 포인터를 다루면 항상 배열이 같이 나온다. 둘 다 주소값을 저장하게 되지만 본질적으로 차이를 보이는데

- 포인터는 주소를 담으며 연산을 통해 주소값이 변경될 수 있다.
- 배열도 주소를 담지만 배열의 시작점에 대한 주소로, 고정된 값을 갖게 된다. 따라서 임의로 변경하는 것은 에러를 불러일으킨다.

```c
int arr[10];
int *ptr;

ptr = arr;  // ✓ Works: assigns arr's address to the pointer variable
arr = ptr;  // ✗ Error: arr is not a variable, it's a fixed label
```
```c
int arr[10];
int *ptr = arr;

ptr++;   // points to arr[1]
arr++;   // error
```

이렇게 보면 배열이 포인터와 비교하여 좋은게 없어 보이지만 배열은 크기 정보를 담고 있다.

```c
int arr[10];
int *ptr = arr;

sizeof(arr) // 40 bytes (entire array)
sizeof(ptr) // 4 or 8 bytes (just the pointer variable)

int num_elements_arr = sizeof(arr) / sizeof(arr[0]);  // Works for arrays
int num_elements_ptr = sizeof(ptr) / sizeof(ptr[0]);  // Doesn't work for pointers!
```

그리고 ```&```사용에도 차이가 있다.
```c
int x = 5;
int *ptr = &x;

&x    // type: int * (pointer to int)
&ptr  // type: int ** (pointer to pointer to int)

int arr[10];

arr   // decays to: int * (pointer to first element)
&arr  // type: int (*)[10] (pointer to array)
```

```&ptr```의 경우 이중 포인터를 의미하지만 ```&arr```의 경우 배열 포인터를 의미한다.

### 왜 ```int (*)[10]``` 타입인가?

처음에는 ```int[10]```의 주소를 의미하는거니까 ```*int[10]```이 아닌가 생각했었다.

그렇지만 C언어에서는 이를 금하고 있다. 기본적으로
```
[base-type] [declarator-with-identifier]
```
의 형태를 이루는데, base-type은 ```int```, ```char```, ```float```같은 녀석들이고, ```*```은 declarator로 구분된다. 이런 문법을 사용하는 이유는 컴파일러 해석의 모호성 때문인데 만약 ```*```를 앞에 썼다고 해보자.
- ```*int [10]``` : 길이 10인 int 포인터를 담는 배열인가?
- ```* int[10]``` : 길이 10인 int를 담는 배열의 포인터인가?

두 가지 해석이 공존하게 된다.

### 왜 괄호를 붙였는가? (```int (*)[10]``` vs ```int *[10]```)

이 부분은 연산자의 우선순위와 관련이 있다. ```[]```는 ```*```보다 우선적으로 고려된다. 그러면
1. ```int *[10]```
2. ```[10]``` : 길이 10의 (...)를 담는 배열
3. ```*``` : 길이 10의 포인터를 담는 배열
4. ```int``` : 길이 10의 int 포인터를 담는 배열

이와 비교하여

1. ```int (*)[10]```
2. ```(*)``` : ...의 포인터
3. ```[10]``` : 길이 10의 (...)를 담는 배열의 포인터
4. ```int``` : 길이 10의 int를 담는 배열의 포인터

결과적으로 C언어의 개발 철학과 관련지을 수 있다. 선언의 형태와 실제 사용되는 형태의 모습을 맞추려고 하다 보니 배열의 경우 저렇게 요소 정보가 뒤로 간 것으로 보인다. 다만 이에 대한 trade-off로 자료형 해석이 안에서 밖으로 이루어지는 등의 난해한 구조 + 추가적인 문법 규칙이 생겨난 듯하다.
실제로 최근에 나온 다른 언어들은 이런 식으로도 사용한다.
```
Go: var arr [10]int
Rust: let arr: [i32; 10]
```

## 함수에 쓰이는 인자로 Pointer와 Array 둘의 차이가 있나?

함수의 인자로 둘 다 전달할 수 있다. 하지만 배열의 경우 포인터로 decay되어 전달된다.

```c
void func(int arr[]) {
    printf("%zu\n", sizeof(arr));  // Prints 8 (pointer size)
}
```

컴파일러는 세 가지 형태 모두에 대해 같은 방식으로 포인터로 처리한다. 하지만 개발자의 시선에서 의도를 심어줄 수는 있을 것이다.

```c
void func(int *arr)     // Honest: "I receive a pointer"
void func(int arr[])    // Suggestive: "I expect an array"
void func(int arr[10])  // Misleading: "I expect 10 elements" (but not enforced!)
```

### Decay되는/되지 않는 예시들
```c
int *ptr = arr;   // ✓ Decay (array → pointer)
sizeof(arr);      // ✗ No decay (needs size info)
&arr;             // ✗ No decay (address of the array itself)
func(arr);        // ✓ Decay (array → pointer)
```


## Character Pointers and Functions

다음 두 가지 경우를 생각해보자.
```c
char amessage[] = "now is the time"; /* an array */
char *pmessage = "now is the time"; /* a pointer */
```
전자의 경우 배열에 한 글자씩 들어가고, 배열 값을 수정할 수 있다. 하지만 후자의 경우 '상수 문자열 리터럴'로써 메모리의 Read only data segment에 저장된다. 따라서 포인터를 통해 접근하는 것은 가능하나, 값을 수정하려고 하면 예기치 못한 동작이 발생할 수 있다.

그리고 같은 상수 문자열 리터럴이 여러 변수에서 사용되는 경우 같은 주소 값을 참조시킴으로써 메모리를 절약할 수 있다.

## 다차원 배열

### 왜 함수에는 첫번째 크기만 free한가?
앞서 작성한 글들을 이해했다면 어렵지 않게 알 수 있을 것이라 생각한다. 1차원 배열을 함수에 넣을 때 실제로 포인터로 decay된다고 하였다. 그러면 base type만 알면 다음 요소의 위치를 주소값 연산으로 참조할 수 있게 된다. 마찬가지로 2차원 배열에서도 다음 요소의 위치를 알기 위해 column의 크기 + base-type가 필요하다.

```c
f(int daytab[2][13]) { ... }  // OK
f(int daytab[][13]) { ... }   // OK
f(int (*daytab)[13]) { ... }  // OK
f(int *daytab[13]) { ... }    // NO
```

### 2차원 배열을 배열 포인터로 나타내기
```c
int a[10][20];
int *b[10];
```

초기화와 함께하면 첫번째 요소 개수를 생략할 수 있다.

```c
char *name[] = { "Illegal month", "Jan", "Feb", "Mar" };
char aname[][15] = { "Illegal month", "Jan", "Feb", "Mar" };
```

## 함수 포인터

### 왜 쓰나?
- 일반적인 함수는 컴파일 타임에 함수가 명시적으로 정해져있어야 한다. 하지만 함수 포인터를 사용하게 되면 이를 유동적으로 가져갈 수 있다.
```c
// Normal: Fixed at compile time
result = add(5, 3);

// Function pointer: Flexible at runtime
int (*op)(int, int) = user_wants_add ? add : subtract;
result = op(5, 3);
```

- 코드가 덜 지저분해진다.
```c
// WITHOUT function pointers (repetitive)
void sort_ascending(int arr[], int size) { /* sort logic */ }
void sort_descending(int arr[], int size) { /* same logic, different compare */ }

// WITH function pointers (reusable)
void sort(int arr[], int size, int (*compare)(int, int)) {
    // One sorting algorithm, any comparison logic
```

- 포인터를 담는 배열을 쓰면 여러 가지 경우의 수에서 효과적으로 함수를 할당할 수 있다.
```c
// WITHOUT function pointers
void execute_command(char cmd) {
    if (cmd == 'a') func_a();
    else if (cmd == 'b') func_b();
    else if (cmd == 'c') func_c();
    // ... 20 more lines
}

// WITH function pointers
void (*commands[26])(void) = {func_a, func_b, func_c, /* ... */};
void execute_command(char cmd) {
    commands[cmd - 'a']();  // Direct lookup
}
```

### 타입 안정성과 이중 포인터의 캐스팅
```c
#include <stdio.h>
#include <string.h>

#define MAXLINES 5000 /* max #lines to be sorted */
char *lineptr[MAXLINES]; /* pointers to text lines */

int readlines(char *lineptr[], int nlines);
void writelines(char *lineptr[], int nlines);

void qsort(void *lineptr[], int left, int right, int (*comp)(void *, void *));
int numcmp(char *, char *);

/* sort input lines */
main(int argc, char *argv[]) {
    int nlines; /* number of input lines read */
    int numeric = 0; /* 1 if numeric sort */
    if (argc > 1 && strcmp(argv[1], "-n") == 0)
        numeric = 1;
    if ((nlines = readlines(lineptr, MAXLINES)) >= 0) {
        qsort((void**) lineptr, 0, nlines-1, (int (*)(void*,void*))(numeric ? numcmp : strcmp));
        writelines(lineptr, nlines);
        return 0;
    } else {
        printf("input too big to sort\n");
        return 1;
    }
}

/* qsort: sort v[left]...v[right] into increasing order */
void qsort(void *v[], int left, int right, int (*comp)(void *, void *)) {
    int i, last;
    
    void swap(void *v[], int, int);

    if (left >= right) /* do nothing if array contains */
        return; /* fewer than two elements */
    swap(v, left, (left + right)/2);
    last = left;
    for (i = left+1; i <= right; i++)
        if ((*comp)(v[i], v[left]) < 0)
            swap(v, ++last, i);
    swap(v, left, last);
    qsort(v, left, last-1, comp);
    qsort(v, last+1, right, comp);
}
```
Q1. 왜 ```void *[]``` 매개변수 자료형은 함수 사용 시 ```v```와 같이 전달되는가? ```v```의 자료형은 무엇인가?

&emsp; 1차원 배열과 같은 방식으로 ```v```가 함수에 전달될 때 첫번째 요소의 포인터로 decay된다. 따라서 type은 ```void**```와 동일하다. 

Q2. 왜 ```(void**)```을 명시하는가?

&emsp; ```lineptr```의 타입은 ```char*[]```이다. 그리고 매개변수는 ```void*[]```이다. 함수에 전달될 때 이중 포인터로 decay되면서 최종적으로 ```char**```, ```void**```이 비교되는데 문제는 C 표준에서 이중 포인터는 ```void```와 다른 이중 포인터 타입 간 호환되지 않는다. 이는 타입 안정성 때문인데 예를 들어 보면
```c
int x = 42;
int *p = &x;
void *vp = p;      // OK
int *p2 = vp;      // OK

char *str = "hello";
char **pp = &str;
void **vpp = pp;   // Warning(Error)
```
왜 이렇게 될까? 먼저 단일 포인터의 경우 포인터는 참조하고자 하는 값의 메모리 주소를 가진다. 만약 ```void*```가 가리키는 값을 이용하고 싶으면 형변환 ```T*```을 통해 명시적으로 어떤 포인터인지 알려주어야 한다. 즉, ```void*```만으로는 역참조가 불가능하다.

```c
int x = 42;
char c = 'A';

int *ip = &x;
char *cp = &c;

// void *로 변환
void *vp1 = ip;  // 주소만 복사
void *vp2 = cp;  // 주소만 복사

// void *는 역참조 불가능!
*vp1;  // ✗ 컴파일 에러! void *는 역참조 못함
```

이중 포인터의 경우에는 양상이 좀 다른데, 역참조하는 대상이 주소값이기 때문에 암시적 형변환이 된다면 문자를 가리키는 주소인지 정수를 가리키는 주소인지 마음대로 바꿀 수 있게 된다.
```c
char *str = "hello";
char **pp = &str;

// 만약 void **가 암묵적 변환 허용한다면?
void **vpp = pp;  // [가정: 이게 자동으로 된다면]그러

// 이제 문제!
int num = 42;
*vpp = &num;  // 단일 포인터는 암시적 형변환 가능

// str 사용
*str = 'X';  // ⚠️ 프로그래머는 str이 char *인 줄 알지만
             // 실제로는 int *!
```

핵심적으로 차이를 보이는 부분은 이중 포인터는 주소 참조라는 점이고, 단일 포인터는 값 참조라는 점인데, 

요약하면 타입을 잘못 역참조하는 인간 실수가 아닌 이상 포인터 ```T*```, ```void*```의 암시적 형변환이 문제가 되지 않는다. 하지만 이중 포인터 ```T**```, ```void**```가 만약 암시적 형변환이 된다면 기존에 정의했던 포인터의 자료형이 바뀌는 문제가 생길 수 있기 때문에 명시적으로 써주어야 한다.

Q4. 이와 별개로, ```void (*)[]```를 받는 경우 함수 사용시 어떻게 표기하고 어떻게 전달되는가?

```c
// 선언 예시
void (*arr_ptr)[10];  // 10개 void 요소를 가진 배열의 포인터

// 함수 매개변수
void func(void (*p)[]);

// 사용 예시
void array[5];
void (*ptr)[] = &array;  // 배열 전체의 주소

// 함수 호출
func(&array);
func(ptr);
```

## 참고
- C에서는 크기가 빈 배열을 선언하는 건 불가능하다. 특정 값으로 초기화하는 경우에는 컴파일러가 알아서 자료형을 결정해줌.

### 배열은 자료형이 뭔가?
```c
int a[10]; // type is int[10]
``` 

### 함수 포인터에서 왜 매개변수의 자료형만 써도 되는가?

함수의 선언에서는 매개변수의 자료형만 적어도 된다.
```c
int add(int, int);
```
마찬가지의 원리가 함수 포인터에도 적용된다. 정의를 했음에도 매개변수의 자료형만 사용하면 됨.
```c
int add(int x, int y) {
    return x + y;
}

int (*op)(int, int) = add;
```

### 그러면 함수 포인터는 주소를 담으니 자료형도 필요없는것 아닌가?

ㄴㄴ 적어도 컴파일러가 기계어 변환 처리를 하기 위한 정보는 명시해두어야 한다.

### 배열의 타입을 모를 때 매개변수로 넣고 싶은 경우
포인터 배열을 이용한다. 일반적으로는 ```int v[]```와 같이 자료형을 알고 있으면 배열을 직접 넣으면 되지만, 모르면 ```void```형을 쓰게 된다. 하지만 ```void```의 경우 크기가 없기 때문에 직접 값을 담을 수 없다(=배열로 만들 수 없다). 따라서 이를 가리키는 포인터 배열을 만들어서 전달하는 방식으로 자료형에 상관없이 매개변수로 사용할 수 있다.
```c
void v[]    // error
void *v[]   // OK

void qsort_int(void *v[], int left, int right);   // example
```
